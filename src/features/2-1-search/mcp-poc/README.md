# MCP 임시 인덱스의 실제 검색 검증

개발 서버의 `/dev/mcp-search`에서만 사용한다. 기존 `/search`, REST 동기화, 운영 인덱스 저장소는 수정하지 않는다. 페이지와 전용 API는 `NODE_ENV=development`일 때만 열리며 프로덕션에서는 404다.

## 실행

1. MCP PoC에서 생성한 `/private/tmp/viewfinder-mcp-app-poc/index.json`을 유지한다. 저장소에 실제 내부 데이터를 복사하지 않는다. 임시 폴더가 정리됐다면 MCP로 다시 생성해야 한다.
2. `npm run dev` 후 `http://localhost:3000/dev/mcp-search`에 접속한다.
3. 같은 브라우저/포트의 기존 설정을 사용한다. 페이지의 **개인 키 등록·변경**에서 기존 설정 모달을 열어 키와 팀 비밀번호를 설정할 수 있다. 저장 후 모달만 닫히며 페이지와 검색어는 유지된다. 키는 마스킹한다. 모달 열기·닫기 및 저장 여부 표시는 Gemini를 호출하지 않지만, 저장 버튼은 기존 모델 목록 확인 요청을 발생시킨다.
4. **임시 인덱스 확인**은 팀 비밀번호 인증 후 임시 파일만 읽는다. Gemini/Figma 호출은 없다.
5. 비용 안내를 확인하고 **Gemini 검색 실행**을 누른다. 해석과 판정은 기본 2회이며 HTTP 503에만 단계별 1회 재시도해 최대 4회다. 기본 모델 503에는 대체 모델 gemini-3.1-flash-lite를 사용하며, 해석에 성공한 대체 모델로 판정도 이어간다. 해석이 재시도 후에도 실패하면 판정을 호출하지 않는다. 요청 횟수는 재시도를 포함한다. 키는 기존 `createGeminiSearchAi(session.apiKey)`에 전달하며 브라우저에서 Google로 직접 요청한다. 환경변수 키를 사용하지 않는다. 불확실한 원문 연결은 경고와 함께 처리하고 근거가 있는 가까운 화면은 부분 일치 추천으로 표시한다.

2026-11-22 확인한 모델은 `gemini-3.5-flash-lite`. [Google 공식 가격표](https://aistudio.google.com/docs/pricing#gemini-3.5-flash-lite)는 유료 입력 $0.30/100만 토큰, 출력(생각 토큰 포함) $2.50/100만 토큰이다. 예시 입력 1만+출력 2천 토큰 합계 $0.008이며 실제 비용의 상한이 아니다. 무료 등급은 사용 한도에 따른다. 수동 재실행마다 추가 요청이 발생한다.

## 검증할 내용

### Gemini API 연결 진단 (A~D)

일반 검색과 이 페이지의 **Gemini 검색 실행**은 동일한 JSON 모드 공통 어댑터를 사용하며 서버 스키마를 전송하지 않는다. 강화된 응답 구조·의미·근거 검증은 브라우저에서 그대로 수행한다. 실제 검색을 확인할 때는 검색 버튼을 사용한다. A~D/D 전용은 별도로 접힌 **개발 전용 요청 실험**이며 C·D에서만 실험 목적으로 서버 스키마를 전송한다. 검색의 성공 여부나 정확도를 대신 검증하는 버튼이 아니다.

개발 전용 페이지의 **Gemini API 연결 진단 (A~D)** 버튼은 저장된 `session.apiKey`만 사용한다. 페이지 진입·렌더링·설정 변경으로 실행되지 않는다. 한 페이지에서 한 번만 실행하며 중복 클릭을 잠근다. 새 페이지에서 수동 재실행하면 추가 사용량이 발생한다.

A 최소 생성 → B JSON 모드 → C 단순 스키마 → D 현재 interpret 스키마 순서이며 첫 실패에서 즉시 중단한다. 단계별 최대 한 번, 전체 최대 네 번, 자동 재시도 없음. 고정 시험 입력만 전송하며 임시 인덱스나 검색어는 읽거나 전송하지 않는다. 모델·엔드포인트·API 버전·temperature·store 설정은 일반 검색의 공통 설정을 재사용한다. 모든 단계의 출력 한도는 1,024토큰이며 나머지 공통 조건은 동일하다. B에서 MIME 설정을 추가하고 C에서 단순 스키마를 추가하며 D에서 현재 스키마로 교체한다.

A~C 성공을 이미 확인했다면 페이지를 새로고침한 뒤 **변경된 D 단계만 검증 (최대 1회)** 버튼을 사용한다. A~C를 반복하지 않으며 기존 D와 같은 입력·설정으로 전송 스키마만 바뀐다. 전체 진단과 D 전용은 하나의 페이지 실행 잠금을 공유하므로 둘 중 하나를 실행하면 두 버튼 모두 잠긴다. 유료 비용 예시는 입력 2천+출력 1,024토큰 약 $0.0032이며 실제 사용량에 따른다.

D 실험은 `INTERPRET_REQUEST_SCHEMA`를 사용하지만 일반 검색/MCP 검색은 이를 전송하지 않는다. 이 실험용 스키마는 conditions와 aliases의 minItems/maxItems 네 제약만 제외한 것이다. 모든 interpret 응답은 기존 `INTERPRET_SCHEMA`로 엄격히 검사하므로 0개/21개 조건, 0개/13개 aliases는 계속 실패한다. 사용자 보고의 A~C 성공·D 400과 오프라인 검증 결과를 구분해야 한다. JSON 모드 복구 후 실제 검색은 아직 미검증이다. HTTP 200이면서 실패라면 배열 길이·출력 종료·응답 형식 검증 실패일 수 있으므로 HTTP 400과 구분해 기록한다.

결과는 단계·HTTP·성공 여부·허용된 Google 코드/상태/필드 경로만 브라우저 메모리에 표시한다. HTTP 200이어도 비정상 종료·빈 텍스트·단계별 응답 형식 실패면 중단한다. 이런 실패가 HTTP 400을 뜻하는 것은 아니다. D는 구조 검증만 수행하며 실제 검색 정확도나 원문 조건의 의미를 평가하는 테스트가 아니다. 네 단계 모두 성공해도 일반 검색의 전체 프롬프트와 요청 조합은 별도 검증이 필요하다.

무료 한도 내 무료이며, 유료 예시 입력 합계 5천·출력 합계 4,096토큰은 약 $0.012다. 정확한 비용은 실제 사용량에 따른다. 이번 구현의 테스트는 fetch를 가짜 응답으로 바꾼 오프라인 테스트이며 실 API 테스트 결과가 아니다. 프로덕션에서는 페이지와 진단 실행을 모두 차단한다.

검색어: `앱서비스 홈 화면에서 콘텐츠가 없을 때 표시되는 Empty View`

- 목록에 `14330:42211`이 있는가? 순위와 판정을 확인한다. 정답 노출을 강제하지 않는다.
- 진단의 조건 개수와 `targetCandidateIncluded`를 확인한다. 민감한 검색 원문·후보 텍스트·모델 원문은 진단에 복사하지 않는다.
- 결과의 원본 링크가 APP 파일을 가리키는가?
- 결과에 표시된 근거 문구가 실제 임시 인덱스의 문구와 일치하는가?
- 실제 문구 “아직 인기글이 없어요”, “아직 최신글이 없어요”를 근거로 사용하는가?
- 대상은 인기글/최신 게시물 영역이 비어 있고 프로필/행사 등은 존재한다. 모든 홈 콘텐츠가 없다고 단정하지 않는가? 영역과 화면 전체 상태를 혼동하면 실패로 기록한다.
- 정보 부족을 불충족으로 단정하지 않고 부분 일치로 안내하는가?
- 첫 번째 결과가 자동 선택되고 다른 결과를 선택할 수 있는가?

진단은 브라우저 컴포넌트 상태에만 보관하며 서버 전송·로그·영구 저장하지 않는다. 실패 시 단계, 오류 유형, HTTP 상태, 허용된 finishReason, 오류 필드 경로를 표시한다. HTTP 오류는 Google 오류 본문을 분석해 허용된 code/status/reason/요청 필드와 판독 상태만 보존한다. message/description/metadata, 알 수 없는 사유와 필드명은 표시하지 않는다. Google이 message에만 사유를 제공하면 구체 원인은 확인할 수 없다. API 키·헤더·민감한 요청/응답 원문은 진단에 넣지 않는다. 이 테스트 경로는 미리보기 REST API를 호출하지 않으며 원본 Figma 링크를 제공한다. 임시 스크린샷 URL은 재사용하지 않는다.

키 상태의 “저장됨”은 현재 브라우저에 기존 사용자 설정이 있다는 뜻이다. 현재 모델·요청 스키마로 실제 검색이 가능한지 검증한 표시는 아니다. 키 상태와 설정 모달의 상태 변경은 오프라인 컴포넌트 테스트로 확인하며 실제 저장 시 API 연결·브라우저 동작까지 검증한 결과는 아니다.

## 데이터의 제한

실제 MCP에서 읽은 4개 화면을 사용한다. 43개 전체 페이지나 216개 구조 후보의 완성 인덱스가 아니다. 컴포넌트·토큰 배열은 미수집이며 실제 부재가 아니다. 페이지 선정은 알려진 정답 위치에 기반했다.

현재 검증기는 평탄한 텍스트를 사용한다. 모델이 일부 영역 근거를 잘못 `scope=screen`이라고 주장하면 정답으로 승격될 수 있다. 이 테스트는 그 오탐을 숨기거나 판정을 강제로 바꾸지 않는다. 화면에 PoC 관측 사실을 별도로 표시하고 조건별 원본 판정을 제공한다.

## 현재 확인 결과

- Chrome에서 페이지 렌더링, 기존 브라우저 세션 사용, 팀 인증 후 임시 화면 4개와 정답 ID 표시 확인.
- 실제 Gemini 검색은 실행 전: 호출 0회. 정답 반환/순위/실제 모델의 범위 판정은 아직 미검증.
- 서버 보호 테스트: 프로덕션 차단, 비밀번호 선확인, 다른 팀 차단, 허용 파일 검증, 캐시 방지, 오류 세부 정보 비노출.

## 확장 전에 필요한 작업

1. 실제 모델 실행 결과의 순위·조건별 근거·영역 범위를 기록하고 위 정답 사례를 실제 데이터 회귀 기준으로 확정한다.
2. 텍스트/인스턴스/상태의 상위 영역 정보를 보존하고 모델의 scope 선언과 대조한다. 공통 형식 변경은 별도 협의한다.
3. MDS 및 토큰 미수집과 실제 부재를 구분하고 컴포넌트와 Variant의 동일 인스턴스 관계를 보존한다.
4. 모든 페이지의 발견/상세 조회/실패/미탐색을 기록하고 응답 바이트 한도에 따라 분할·재개한다. 모바일 크기만 사용한 PoC 후보 규칙을 PC/작업용 컨테이너에 확장한다.
5. 승인된 파일 레지스트리 범위, `fileKey + nodeId` 식별자, 페이지별 후보 할당 및 후보 상한에 따른 정답 누락을 검증한다.
6. 수집 결과를 별도 임시 파일로 검증한 후 운영 반영을 별도 작업으로 설계한다. VS Code의 MCP 인증이 배포 웹에 자동 공유되는 것은 아니다.
